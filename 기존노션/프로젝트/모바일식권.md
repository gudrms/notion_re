기술적 도전과 창의적 해결 과정

1. QR 인식률 문제
2. 태블릿 장비를 센터에서 식당에 대여 후 식당에서 식당 계정으로 회사 페이지에 로그인 후 식권 사용 시스템으로 식당의 관리자 권한
3. 식권 사용에 이슈가 있을 때 문제 해결(관리자 페이지에서 사용처리)
4. 최초 로그인 후 계정으로 식권을 발급하여 사용 처리를 하였으나 로그인이 꼭 필요한지 등 로그인을 제외하자는 새 기획으로 운영 중인 프로세스 변경
5. his 병원 시스템과 식권 관리 페이지의 데이터 연동

첫 번째 : "QR 인식률 문제 - 이론과 현실의 차이"
개발 환경에서는 100% 인식되던 QR코드가 실제 현장에서는 낮은 인식률을 보였습니다.

문제 분석:

- 스마트폰 화면 밝기 차이 (실내/실외)
- 사용자별 손떨림 정도
- 연령대별 QR 스캔 숙련도 차이
- 자판기 스캐너와의 거리/각도 문제

창의적 해결책:

- QR 코드 크기 최적화: 3cm → 5cm (가독성 향상)
- Error Correction Level 상향: M(15%) → H(30%) (손상 허용도 증가)
- 스캔 가이드라인 추가: 화면에 정확한 스캔 위치 표시
- 음성 피드백: "스캔 성공", "다시 시도해주세요" 안내
- 최종 결과: 인식률 99.2% 달성

두 번째 : "태블릿 장비 대여 및 식당 계정 관리"
센터에서 식당으로 태블릿을 대여하고, 식당 직원이 식당 계정으로 회사 페이지에 로그인하여 식권 사용 처리를 하는 복잡한 프로세스가 필요했습니다.

해결 과정:

- 식당별 전용 계정 생성 및 권한 관리 시스템 구축
- 태블릿 대여 시 자동 로그인 설정으로 식당 직원의 편의성 향상
- 관리자 페이지에서 식당별 사용 현황 실시간 모니터링

세 번째 : "식권 사용 이슈 발생 시 즉시 대응"
식권 사용 중 오류나 문제 발생 시 현장에서 즉시 해결할 수 있는 관리자 도구가 필요했습니다.

해결 과정:

- 관리자 페이지에서 실시간 사용 처리 및 취소 기능 개발
- 이슈 발생 시 즉시 알림 시스템 구축
- 원격으로 식권 상태 변경 및 재발급 기능 제공

네 번째 : "운영 중 프로세스 변경 - 로그인 필수에서 선택으로"
초기에는 로그인 후 식권 발급 방식이었으나, 사용자 편의성을 위해 로그인 없이도 사용 가능하도록 기획 변경이 요구되었습니다.

해결 과정:

- 기존 로그인 기반 시스템을 유지하면서 비로그인 방식 추가 구현
- 두 가지 방식의 데이터 일관성 보장을 위한 백엔드 로직 설계
- 사용자 선택에 따른 동적 UI 변경 및 처리 프로세스 분기

다섯 번째 : "HIS 병원 시스템과의 데이터 연동"
기존 병원 시스템(HIS)과 새로운 식권 관리 페이지 간의 실시간 데이터 동기화가 필요했습니다.

해결 과정:

- HIS 시스템 API 분석 및 연동 인터페이스 설계
- 실시간 데이터 동기화를 위한 배치 프로세스 구현
- 데이터 불일치 발생 시 자동 보정 및 알림 시스템 개발
