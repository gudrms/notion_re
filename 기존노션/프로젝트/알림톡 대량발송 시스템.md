## **대량 알림톡 발송 시스템 구축**

📅 기간 : 2026.01 ~ 02

👥 팀 구성 : 1명

🎯 역할 : 백엔드 개발자

🛠 기술 스택

- Backend : Node.js, NestJS, TypeScript, TypeORM
- Database : PostgreSQL
- Queue : Bull Queue, Redis, ioredis
- API : KICS API (비즈톡 중계)

## **🎯 주요 구현 내용**

### **1️⃣ Bull Queue 기반 비동기 배치 처리 시스템**

- Redis 기반 작업 큐 설계 및 구현
- 100건 단위 배치 처리로 메모리 효율화
- Worker 프로세스 분리로 운영 서버 부하 최소화

### **2️⃣ Rate Limiting으로 TPS 제어**

- 4단계 속도 프리셋 구현 (CONSERVATIVE, NORMAL, FAST, AGGRESSIVE)
- 초당 300건 ~ 2,000건까지 상황별 조절 가능
- 기본 설정(FAST): 초당 1,000건 처리

### **3️⃣ 대량 데이터 처리 최적화**

- 청크 단위 처리로 메모리 사용량 80% 절감
- Partial Index로 PENDING 조회 성능 50% 향상
- Autovacuum 튜닝으로 대량 INSERT 안정화

### **4️⃣ 테스트 모드 및 운영 안정성**

- 실제 발송 없는 테스트 모드 구현
- 실패 자동 재시도 로직 (최대 3회, 지수 백오프)
- 작업 상태 추적 및 실시간 진행률 모니터링

### **5️⃣ 작업 제어 및 장애 대응 시스템**

- **일시정지/재개 기능으로 130만건 발송 중 안전한 중단 및 이어보내기 구현**
- **Queue 대기열 자동 정리 및 SENDING→PENDING 상태 복구로 중복 발송 방지**
- **작업 취소 시 이미 발송 완료 건 보존, 미발송 건만 정리**
- **실패 건 선별 재시도 (retryCount 기반, 최대 3회)**
- **Job 완료 자동 감지 (pendingCount=0 시 COMPLETED 자동 전환)**

## **💡 기술적 성과**

### **성능 개선**

- **처리 속도**: 130만 건을 22분 내 완료 (초당 1,000건)
- **메모리 효율**: 청크 단위 처리로 대용량 데이터 안정적 처리
- **DB 최적화**: SQL 레벨 원자적 연산으로 동시성 문제 해결

### **운영 효율화**

- 테스트 모드로 실제 발송 전 안전한 검증 가능
- 4단계 프리셋으로 시간대별 유연한 속도 조절
- **일시정지/재개로 장애 발생 시 즉시 대응 후 이어서 처리 가능**
- Swagger 문서화로 API 사용성 향상

### **확장성 & 유지보수성**

- Entity, Repository, Service 계층 분리로 명확한 책임 구조
- 상세한 테스트 시나리오 및 체크리스트 문서화
- 내년 발송 시 2단계 API 호출만으로 완료 가능

`[대상자 적재] → [작업 생성]
      ↓

      ↓
[KICS API 호출] → [비즈톡 발송]
      ↓
[결과 처리 & 상태 업데이트]

[자동 완료 감지 / 실패 건 재시도]`

### **핵심 테이블 구조**

- `tb_kakao_batch_job` : 발송 작업 관리 (상태, 진행률, 카운트)
- `tb_kakao_batch_target` : 개별 대상자 관리 (130만 건)

## **🔍 주요 기능**

### **API 엔드포인트**

- `POST /api/notification/kakao/batch/jobs` - 작업 생성
- `POST /api/notification/kakao/batch/jobs/:jobId/start` - 발송 시작
- **`POST /api/notification/kakao/batch/jobs/:jobId/pause` - 일시정지**
- **`POST /api/notification/kakao/batch/jobs/:jobId/resume` - 재개 (이어보내기)**
- **`POST /api/notification/kakao/batch/jobs/:jobId/cancel` - 취소**
- **`POST /api/notification/kakao/batch/jobs/:jobId/retry` - 실패 건 재시도**
- `GET /api/notification/kakao/batch/jobs/:jobId/status` - 실시간 진행 현황
- `DELETE /api/notification/kakao/batch/jobs/test-mode/all` - 테스트 데이터 정리

### **속도 프리셋**

| **프리셋** | **TPS** | **130만 건 소요 시간** | **용도** |
| --- | --- | --- | --- |
| CONSERVATIVE | 300건/초 | 72분 | 테스트/검증 |
| NORMAL | 500건/초 | 43분 | 일반 운영 |
| **FAST (기본)** | **1,000건/초** | **22분** | **권장** |
| AGGRESSIVE | 2,000건/초 | 11분 | 긴급 발송 |

### **작업 상태 흐름**

`READY → RUNNING → COMPLETED
          ↓ pause     ↑ resume
        PAUSED ───────┘
          ↓ cancel
       CANCELLED → retry → RUNNING`

## **🎓 배운 점**

- **대용량 처리 경험**: 130만 건 데이터를 안정적으로 처리하는 전략 수립
- **비동기 작업 큐 설계**: Bull Queue를 활용한 분산 처리 시스템 구축
- **성능 최적화**: DB 인덱싱, 청크 처리, Rate Limiting 등 다양한 최적화 기법 적용
- **운영 고려 설계**: 테스트 모드, 재시도 로직, 모니터링 등 실제 운영을 고려한 시스템 설계
- **장애 복구 설계**: 중단 후 이어보내기, 중복 발송 방지, 상태 복구 등 장애 상황을 고려한 안전한 시스템 설계
