              ## — 동의서 SQL 성능 튜닝

              ### 문제

              동의서 처리 로직에서 사용되는 **TB_CON*** 계열 테이블**에서

              반복적인 **Full Scan**과 **채번 방식 문제**로 성능 지연이 발생

              ### 원인

                1. **CON*** 계열 테이블 풀스캔 반복**
                2. **MAX 기반 채번 로직**으로 동시성 병목

              동의서 테이블은:

                - 읽기 빈도가 **매우 높은** 구조
                - 동시 접근 다수
                - **온라인 트랜잭션 테이블**

              이었음에도 **인덱스 설계가 부족**했고,

              채번 방식이 **MAX 조회 기반**이라 경쟁 구간이 발생

              **실제 응답 시간:**
              → **3~4초 수준**
                
              ---

              ### Before 지표

              | 항목 | 수치 |
                              | --- | --- |
              | 실행시간 | 3~4초 |
              | 접근 방식 | STORAGE FULL SCAN |
              | CON*** Logical I/O | 125,853 |
              | CON*** Physical I/O | 과다 |
              | 동시성 | 채번 경쟁 발생 |

              풀스캔으로 **12만 블록 이상 접근**.

              → 소량 조회인데 **대용량 스캔 발생**
                
              ---

              ### 분석 접근

              ### 1. 인덱스 부재로 인한 Full Scan

              **CON*****는:

                - 쓰기보다 **읽기가 압도적으로 많은** 테이블
                - 운영 통계 기준으로 인덱스 추가가 가능한 구조

              **실행계획:**

                ```
                STORAGE FULL SCAN
                ```

              → 불필요한 대규모 I/O
                
              ---

              ### 2. MAX 기반 채번 문제

              **기존 채번 방식:**

                ```sql
                SELECT MAX(col) + 1
                ```

              이 방식은:

                - 테이블 스캔
                - 동시 세션 경합
                - **rigth-growing 문제**
                - **latch/redo 증가**

              → 고전적인 **OLTP 병목 패턴**
                
              ---

              ### 3. 시퀀스 latch 경합 대응

              시퀀스로 변경 후:
              → **high concurrency 환경에서 latch 경합 발견**

              **해결 전략:**

                - `CACHE` 옵션 적용
                - 업무팀과 협의
                - 번호 연속성 불필요 확인
                - 유일성만 보장

              → 적절한 **cache 크기 설정**
                
              ---

              ### 핵심 전략

                ```
                1. CON*** 핵심 컬럼 인덱스 추가
                2. Full Scan → Index Range Scan 전환
                3. MAX 채번 제거
                4. Sequence 기반 채번 구조 변경
                5. Sequence cache 옵션 적용
                ```
                
              ---

              ### After 결과

              | 항목 | 수치 |
                              | --- | --- |
              | 실행시간 | **1초 이하** |
              | 접근 방식 | **Index Range Scan** |
              | Logical I/O | **83** |
              | Physical I/O | 최소화 |
              | 채번 병목 | 제거 |

              **성과:**

                - **Full Scan 완전 제거**
                - 약 **1,500배 I/O 감소**
                - 응답 시간 **70% 이상 개선**

                ---

              ### 기술적 의미

                1. **OLTP 구조에 맞는 인덱스 재설계**
                2. **채번 알고리즘 개선**
                3. **동시성 안정화**
                4. **latch 경합 제거**

              **→ 데이터 접근 패턴 기반 설계로 전환**
                
              ---

              ### 배운 점

                - **읽기 위주 테이블은 적절한 인덱스 필요**
                - **MAX 채번도 사용 가능하지만 성능에는 시퀀스 사용 권장**
                - 시퀀스는 **cache 옵션의 중요성**
                - **동시성은 SQL보다 구조 문제**
                - 튜닝은 **업무 요구사항과 같이 봐야** 함

                ---

    8. 정적 리소스 캐시 사용

    9. 로깅 최적화

- 해결 과정에서의 도전과 시행착오

  첫 번째: 다부서 요구사항의 충돌

  각 부서마다 상반된 요구사항:

    - 홍보팀: "브랜드 이미지에 맞는 세련된 디자인"
    - 의료기획팀: "의학적 정확성과 법적 완결성"
    - 법무팀: "전자서명의 법적 효력 보장"
    - 정보보안팀: "개인정보 최고 수준 보안"
    - 현업(접수팀): "빠르고 간단한 처리 및 컴플레인의 최소화"

  해결 과정: 우선순위 기반 단계적 접근

    - 1단계: 법적 효력 + 보안 (필수 요구사항)
    - 2단계: 사용자 편의성 (고연령층 고려)
    - 3단계: 디자인 + 브랜딩 (부가 요구사항)
    - 매주 다부서 회의를 통한 진행상황 공유 및 피드백 수렴

  두 번째: 고연령층을 위한 UX 설계

  50-70대 고객이 50%인 상황에서 일반적인 웹 UI로는 한계

  사용자 리서치 과정:

    - 임직원 30명 대상 1:1 사용성 테스트
    - 관찰된 문제점: "버튼이 작다", "어디를 누를지 모르겠다", "글씨가 안 보인다"

  해결책:

    - 폰트 크기와 버튼 크기 확대 (홍보팀 반발 → 사용자 편의성 우선 결정)
    - 고대비 색상 적용, 명확한 CTA 버튼 배치

  세 번째: 실시간성과 데이터 동기화

  와콤 태블릿을 통한 화면 동기화가 가장 복잡

  기술적 문제:

    - 실시간 동기화: 수검자 화면(자식창) ↔ 직원 화면(부모창) 즉시 반영
    - 와콤 태블릿 연동: 태블릿에서 서명 → 즉시 PC 화면에 표시
    - 크로스 플랫폼 대응: PC, 와콤 태블릿, 모바일 각각 다른 해상도와 입력 방식

  해결 과정:

    - DOM 기반 실시간 동기화: 자식창에서 발생한 이벤트를 부모창 DOM에 즉시 반영
    - 서명 데이터 최적화: Canvas 데이터 → Base64로 변환하여 DOM에 즉시 반영
    - 반응형 UI 설계: PC(1920×1080), 태블릿(1024×768), 모바일(375×667) 각각 최적화
    - 입력 방식 자동 감지: 터치, 마우스, 와콤 펜 입력을 자동으로 구분하여 처리

  네 번째: 무리한 현업 요구사항 관리

  대응 전략:

    - 우선순위 매트릭스 도입: 긴급도 × 중요도 4분면으로 요청사항 분류
    - 변경 영향도 분석: 새 요구사항이 기존 기능에 미치는 영향 즉시 분석
    - 현실적 일정 제시: "24시간 내 구현 시 발생 가능한 리스크" 명확히 커뮤니케이션
    - MVP 접근: 핵심 기능만 우선 구현 후 점진적 개선
- 측정 가능한 비즈니스 임팩트
    - 사전 동의율 증가: 현장 작성 100% → 사전 작성 95% (대기시간 50% 단축)
    - 처리 속도 향상: 동의서 작성 시간 평균 약4분 → 1분 미만 (80% 단축)
    - 비용 절감: 외부 솔루션 의존도 제거로 연간 2,000만원 절약
    - 개발 효율성: 양식 수정 시간 2주 → 2시간 (99% 단축)
    - 현장 작업 효율: 동의서 안내 및 작성 시간 연간 약 12,000시간 절감
    - 다양한 환경 지원: PC/태블릿/모바일 모든 환경에서 동일한 사용자 경험 제공
- 이 경험에서 배운 것

  외부 솔루션에 의존하는 것의 위험성을 몸소 체감했습니다. "비용"만이 아니라 "통제권"의 중요성을 깨달았죠. 내재화를 통해 우리가 원하는 타이밍에 원하는 기능을 추가할 수 있게 되었고, 갑작스런 법정 양식 변경에도 24시간 이내에 새로운 동의서 양식을 배포할 수 있었습니다.

  기술적으로는 "다부서 조율"의 중요성을 배웠습니다. 아무리 좋은 기술이라도 이해관계자들의 합의 없이는 성공할 수 없다는 것, 그리고 때로는 기술적 완벽함보다 정치적 타협이 더 중요할 수 있다는 현실적 교훈을 얻었습니다.
